# 지식 검증 (knowledge-check)

## 목적
field-note(사장님이 먼저 말함)의 **반대 방향**. Claude가 위키에 이미 쓴 장기렌트 지식을 짧은 문장으로 보여 주고 사장님이 맞다/틀리다만 답한다. 결과는 field-note와 **같은 칸·같은 형식**(`## 확정 사실 (사장님 확인)`, `## 현장 설명 (사장님)`)으로 들어가므로 글쓰기 코드·`wiki_factcheck.py`는 바꿀 것이 없다.

## 도구
`python3 ~/second-brain/scripts/knowledge_check.py` — next·asked·ok·wrong·fix·skip·add·gap·status (사용법은 파일 맨 위).
- 진행 상태: `~/projects/_data/shared/work/knowledge-check/state.json` (세션이 끊겨도 이어짐)
- 사람이 보는 진행표: `~/second-brain/wiki/discussions/지식검증-진행.md` (`status`가 다시 씀)
- 사장님 답·확인 결과 기록: `~/second-brain/wiki/discussions/지식검증-기록.md` (Claude가 차례마다 덧붙임)
- 대상: 위키 `concepts/` 중 태그 `글감` 페이지의 핵심 요약·작동 원리·흔한 오해·확인 방법·예외 칸. `지금 상황 요약`(매주 자동 재작성)·근거·관련 페이지·이미 확정된 문장은 뺀다.
- 순서: 검색 수요 높은 페이지 먼저, 그 안에서 '대부분·보통·드물다·회사마다·수 있다' 같은 흐린 문장 먼저(11-15에 틀린 곳이 여기였다).

## 답 받는 방식 (2026-11-15 사장님 시험 후 결정)
- **기본 = 버튼 창(AskUserQuestion) 한 번에 4문장.** 선택지 '맞음 / 틀림 / 모름·넘김', 고칠 때는 사장님이 '기타'에 직접 쓴다. 문장마다 `[주제 n/4]`를 붙여 창만 봐도 알게 한다. 사장님은 '기타'에 길게 설명하는 경우가 많다 — 이게 가장 값진 답이니 고침으로 처리한다.
- 사장님이 채팅 방식(10개씩, 'ㅇ'·'3 x')을 원하면 아래 3번 형식으로.
- 고침을 반영한 뒤 애매한 곳(전부/일부, 개인/법인, 대형/중소형)은 **버튼 창으로 되물어** 확정한다(gotchas).

## 한 차례 진행 (10개씩)
1. `knowledge_check.py next 10` → 후보 문장(ID 포함).
2. 각 문장을 **사실 하나짜리 짧은 평서문**으로 다시 쓴다. 뜻은 그대로, 숫자 없이, 어려운 말은 괄호로 풀이. 두 사실이 섞였으면 더 중요한 하나만 묻는다(ID 하나 = 문장 하나). 각각 `asked ID "보여 준 문장"`으로 기록.
3. 사장님께 이렇게 보여 준다(페이지 이름은 쉬운 말로):
   ```
   📋 저신용·무심사 장기렌트 (1/3차)
   1. 장기렌트도 계약 전에 신용 심사를 한다.
   2. …
   답: ㅇ = 전부 맞음 · 3 x = 틀림 · 4 고침: 내 말 · 7 ? = 모름/넘김 (안 적은 번호는 맞음)
   ```
4. 답 처리:
   - **맞음**(ㅇ 또는 안 적은 번호): `ok ID ID …` → 그 페이지 확정 사실 칸에 자동으로 들어간다(백업 자동).
   - **고침**: ① `python3 ~/second-brain/scripts/field_note.py save "<사장님 말 그대로>"`(원문 보관) ② `fix ID "<사장님 말>"` ③ 그 페이지 `## 현장 설명 (사장님)`에 `- YYYY-MM-DD · <정리한 문장>` ④ 확정 사실 칸에 사장님 문장 `(YYYY-MM-DD 확인)` ⑤ AI 문장을 고친다 ⑥ 같은 주장이 다른 페이지에도 있으면(grep) 같이 고친다. 바꾼 문장을 한 줄씩 보고.
   - **틀림**(x만, 이유 없음): "맞는 내용을 한 줄로 알려 주시겠어요? 모르면 '삭제'"를 **한 번만** 묻는다. 답이 오면 고침과 같게, '삭제'면 AI 문장을 지우고 `wrong ID "삭제"`.
   - **모름/?**: `skip ID` (다시 안 묻는다. 위키 문장은 그대로).
5. **기록 남기기**: 차례마다 `~/second-brain/wiki/discussions/지식검증-기록.md`에 주제별로 덧붙인다 — 위키(AI) 문장 → 사장님 답(원문 파일 이름) → 되물음과 답 → Claude 확인 결과(일치/반박, 근거 링크) → 결과(어느 칸에 무엇을). 공통 기준이 새로 나오면 맨 위 '공통 기준'에.
6. 다음 차례로 넘어가기 전 `status`로 남은 수를 한 줄 보고.

## 사장님 답 확인하기 (2026-11-15 사장님 지시)
사장님 답 중 **확인할 수 있는 부분(법조문·공식 안내·약관·신청서·신용평가사 설명)은 반영 전에 확인**한다.
1. 위키(index·sources)에서 먼저 찾고, 없으면 법령 원문(law.go.kr·casenote)·공식 자료를 웹으로 본다.
2. 사장님 설명과 **같으면** 페이지에 `> [!note] 확인 기록 (날짜, Claude)` 콜아웃으로 근거(조문 번호·자료명)를 남긴다.
3. **다르면** 반박한다: 버튼 창으로 "공식 자료는 ○○라고 하는데 현장에서는 어떤가요?"를 근거와 함께 묻는다. 사장님 답을 확정 사실로 넣고, 어긋난 공식 자료는 확인 기록 콜아웃에 그대로 남긴다(지우지 않는다).
4. 확인을 못 했으면 "확인 못 함"이라고 적는다. 추측으로 '일치'라고 쓰지 않는다.

## 빠진 것 (2단계)
`next` 출력에 "문장 확인 끝, 빠진 것 아직 안 물어본 페이지"가 뜨면 그 페이지에 대해 한 번만 묻는다:
"〈주제〉에서 고객이 자주 묻는데 위키에 없는 것, 또는 현장에서만 아는 것이 있으면 편하게 말씀해 주세요. 없으면 '없음'."
- 도움이 되게 그 페이지 주제지도 백로그의 "못 답한 세부 질문" 2~3개를 예로 붙인다.
- 답은 **field-note 스킬 순서 그대로**(원문 저장 → 현장 설명 → 확정 사실은 확인 후). 끝나면 `gap 페이지 "요약 또는 없음"`.
- 전체 문장이 다 끝나면 마지막으로 "장기렌트 전체에서 빠진 주제"를 한 번 더 묻는다.

## 일반 지식 문장 (선택)
주제지도에서 근거가 '약함·보강 필요'인 페이지는 Claude가 아는 일반 지식으로 문장을 더할 수 있다: `add 페이지 "문장"` → 보여 줄 때 "(일반 지식)" 표시. 맞음이면 확정 사실로, 위키 본문에도 넣는다.

## 마무리 (세션 끝날 때)
`status` → 진행표 갱신. `wiki/log.md`에 `## [날짜] update | 지식 검증 N개(맞음·고침·모름 수)` + 바뀐 페이지. 색인은 매일 05:50 자동.

## 하지 않는 것
- 사장님이 말하지 않은 조건("일반적으로", "약관에 따라")을 붙이지 않는다. 사장님 말과 위키가 다르면 사장님이 맞다.
- 이 스킬 폴더(`_meta`, 공개 리포)에 문장·답변 같은 사업 지식을 적지 않는다. 진행 상태는 `_data`에만.
