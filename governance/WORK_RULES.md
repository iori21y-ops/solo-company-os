# 일하는 방식 (WORK_RULES)

> 무엇을 정하는 파일: 사장님과 소통하는 법, 추측 금지, 완료 보고, 동시 세션, 세션 관리, Linear 기록, 비용, 실행 환경.
> 마지막 갱신: 2026-11-11 · **이 파일이 원본 — 다른 문서는 여기를 가리킨다.** 지도: [RULES_MAP.md](RULES_MAP.md)

## 1. 소통 (사장님 결정 7, 2026-11-11)
- 사장님은 비개발자 — **한국어**로, 간결하게. 전문 용어는 괄호 안에 쉬운 설명.
- **정보가 충분하고 되돌릴 수 있는 일** → "무엇을 왜" 한 줄 말하고 **바로 실행**. 추천은 1개만 (설문 금지).
- **확신이 없거나 되돌릴 수 없는 일** → 먼저 질문 (되돌릴 수 없는 일 목록: [SAFETY_RULES.md](SAFETY_RULES.md) §1).
- 결론·결과부터, 과정은 뒤에. 군더더기·같은 요약 반복 금지.
- 시키지 않은 과잉 작업 금지. "조사만" 요청이면 발견을 보고하고 멈춘다.
- 진짜 막혔을 때만 멈춘다. "하겠습니다" 약속으로 끝내지 않는다.
- 바꾼 뒤에는 사장님이 브라우저·터미널에서 직접 확인하는 방법을 알려 준다.
- 안전 규칙·명시적 프로젝트 규칙은 위 원칙보다 항상 우선.

## 2. 추측 금지 (2026-05-15 박제)
- 순서: ① 관련 코드·API 먼저 읽기(grep·cat·find) → ② 데이터 흐름 파악(어디서 읽고 어디에 쓰나) → ③ 설계 → ④ 실행.
- 코드를 안 읽고 추측으로 스크립트를 짜거나 실행하지 않는다. "아마 ~일 것"으로 방향을 잡지 않는다.
- 새 외부 도구를 들이기 전에 기존 코드가 이미 해결하는지 확인한다.
- 모를 때: "모릅니다. 확인하려면: [명령]" 으로 보고. 추정이 필요하면 "~로 추정됩니다. 확인할까요?" → 승인 후 진행.
- 교훈(차량 이미지 작업, 2026-05): 기존 이미지 처리 코드를 먼저 읽었으면 30분이면 끝날 일이었는데, 추측으로 도구 설치·검토부터 해서 몇 시간이 걸렸다.
- 문서 기술을 맹신하지 않는다 — 중요한 사실(배포 여부·예약 작업 상태)은 그때그때 실측한다.

## 3. 완료 보고
- "완료/통과"는 **실제 도구 결과**(테스트·로그·조회 결과)를 근거로 말한다. 확인 못 했으면 "미검증"이라고 적는다.
- 보고 형식: 대상 / 바꾼 내용 / 검증 결과 / 주의할 점(후속 작업·다른 시스템 영향).

## 4. 동시 세션
- 같은 저장소에는 Claude 세션 **1개만** 작업한다 (2026-07-11 측정 오염·변경 섞임 사고).
- 작업 시작 전 `git status --short` → 다른 세션의 미커밋 변경이 있으면 **먼저 보고**. 남의 변경은 커밋에 섞지 않는다 ([GIT_DEPLOY_RULES.md](GIT_DEPLOY_RULES.md) §3).
- 실험·측정은 작업 트리가 깨끗할 때만.
- git 밖 파일(`outbox/`, `data/`)을 다시 만들거나 덮어쓰기 전: `git log --since="6 hours ago"`와 파일 수정 시각을 보고, 다른 세션 흔적이 있으면 멈추고 묻거나 새 파일 이름으로 쓴다 (2026-11-11 초안 덮어쓰기 사고).
- 예약 작업이 돌았다고 가정하기 전에 `launchctl list`로 확인 (사장님이 직접 끄기도 한다).

## 5. 세션 관리
- 세션 시작 직후 `/advisor` 실행 → Opus 선택 권장.
- 컨텍스트 압축·응답 일관성 저하·긴 파일 반복 읽기가 보이면 즉시 멈추고:
  1. 한 일·바꾼 것·남은 일을 메모리(project/feedback)에 저장
  2. 사장님께 "세션 용량 과다로 성능 저하가 감지되었습니다. 새 세션을 열고 아래 메시지를 붙여넣어 작업을 이어가세요." 안내
  3. 새 세션용 인계 메시지(남은 일·현재 상태·다음 단계) 제공. 긴 인계는 `~/projects/_meta/handoff/`에 파일로.
- 새 세션은 메모리를 읽어 맥락을 복원한다.

## 6. 작업 기록 = Linear
- 워크스페이스 Rentailor, 팀 **REN**, 프로젝트 렌테일러 / 임포리스. 도구는 Linear MCP(productivity 플러그인, 2026-11-11 정상 확인). ERP 작업 목록과는 동기화하지 않는다.
- "REN-N 진행"이라고 하면 그 이슈(설명·🩺 자동 진단 댓글 포함)를 먼저 읽고 시작.
- CADAM·임포리스 작업을 마치면(또는 세션 종료 요청 시):
  1. 관련 REN 이슈에 한 일·결과·검증 근거를 댓글로, 끝났으면 완료 처리
  2. 남은 일·후속 확인은 새 이슈로 (맞는 프로젝트·라벨·마감일) — 메모리에만 남기지 않는다
  3. 커밋 메시지에 `Refs REN-N`(완료면 `Fixes REN-N`) → push 때 이슈에 자동 연결·완료
- 라벨 `자동 등록` 이슈는 점검 스크립트가 열고 닫는다. 직접 고쳐도 다음 정상 실행 때 자동으로 닫힌다.

## 7. 비용
| 대상 | 규칙 |
|---|---|
| Supabase | **무료 플랜 안에서만**. 프로젝트 2개(cadam·importlease)로 꽉 참 → 새 프로젝트 제안 금지. DB 500MB/프로젝트·스토리지 1GB·전송 5GB/월. 대량 입력·새 표·이미지 업로드 전 용량 확인하고 영향 먼저 알림. 이미지는 Supabase Storage 말고 다른 곳 검토 |
| Vercel | 렌테일러는 Hobby(무료) 요금제 = 상업 이용 정책 위반 상태 → 비상 이전 준비(`cadam/docs/netlify-standby.md`). 빌드·배포 횟수를 늘리는 작업은 주의 |
| 영상 제작 | Remotion은 4명 이상 회사면 유료 라이선스 → 기본 제작은 **HyperFrames** |
| 외부 API | 호출 한도가 있는 API는 하루 예산을 둔다(예: 오피넷 주유소 1,200회/일). 한 수집기가 한도를 다 쓰면 같은 키의 다른 수집기도 멈춘다 ([COLLECT_RULES.md](COLLECT_RULES.md)) |
