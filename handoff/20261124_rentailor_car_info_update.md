# 인수인계 — 렌테일러 차종 정보 업데이트 (차종 정보 개편 후속)

> 작성 2026-11-24, 이전 세션: 차종 정보 개편 1~5단계 끝낸 세션. 이 파일은 공개 리포(_meta)라 고객·매출 정보는 적지 않음.
> 사실 표시: `[확인함]` = 이번 세션에 DB·파일을 직접 열어 봄 / `[추정]` = 숫자·이름만 보고 짐작 → 새 세션은 `[추정]`부터 확인.

## 🔑 새 창 빠른 복귀
- **지금 위치**: 개편 구조(엔진 → 트림 → 구동 → 인승 → 색상 → 옵션, 차즘 연결표)는 만들어서 운영 사이트에 배포까지 끝남. 이제 **그 구조에 들어갈 차종 자료의 빈칸·불일치를 채우고 고치는 일**만 남음.
- **핵심 왜**:
  1. 사이트 차량 자료의 원본은 **맥미니 로컬 DB `cadam`의 `car` 스키마**다. 운영 Supabase 차량 표는 11-12부터 동결돼 있어 고치지 않는다. 로컬 DB를 고치면 `car_publish.py`가 사이트 JSON으로 내보내 배포한다(매일 12:30, 또는 kick 10분 뒤).
  2. 렌트료는 계산식 금지, 차즘 실측만 쓴다. 차량가는 **공식 가격표가 우선**이다(결정 4).

## 1. 이어가는 중
새 작업이 아니라 「렌테일러 차종 정보 개편」(결정표 `~/projects/cadam/docs/decisions/2026-11-24-rentailor-trim-structure.md`)의 후속이다. 시작 전에 결정표 전체(특히 결정 4·10·12·14·15·16, '1~4단계 결과'·'정리·5단계')를 먼저 읽는다.

## 2. 큰 그림 (왜 하는가)
- 고객은 제조사 견적처럼 [내 차 만들기] 한 페이지(`/cars/[slug]/options`)에서 차를 고르고, 고른 사양은 상담 신청 → AI 리포트 → 매니저 실 견적으로 넘어간다.
- 화면은 DB 칸이 비어 있으면 그 단계를 건너뛰거나 '기본'만 보여 준다. 그래서 **칸이 비면 고객이 제대로 못 고르고, 매니저에게 넘어가는 정보도 빈다.**
- 이번 업데이트의 목표는 판매 중인 모든 차가 엔진·트림·구동·인승을 빠짐없이, 공식 가격표와 같은 값으로 갖추게 하는 것이다.

## 4. 지금 자료 상태 (11-24 18시 이후, 판매 중·가격 있는 트림 477개)
- 기본 엔진은 477개 모두 채워져 있다 [확인함]. 단 **전기·수소 136개는 `engine_label`이 '전기'·'수소'뿐**(`engine_src='fuel'`, `engine_cc` 없음)이다 [확인함]. 그래서 전기차는 엔진 단계가 사실상 하나로 묶인다. 배터리·모터(스탠다드/롱레인지, 2WD/AWD) 구분이 필요한지는 사장님 판단 거리.
- **기본 인승이 빈 트림은 62개다** [확인함]: 봉고3 27·포터2 18(화물, **결정 14로 보류**), 스타리아 계열 13(스타리아 6·일렉트릭 3·하이브리드 2·라운지 1·라운지 하이브리드 1), 렉스턴 2, 레이 EV 2. 스타리아·렉스턴·레이 EV 17개는 좌석 구성이 여러 개라 자동으로 못 채웠다. 공식 가격표로 하나씩 확인해야 한다.
- **구동(`drive_type`)이 빈 트림은 178개다** [확인함]. 화면 구동 단계의 '기본 (2WD)' 같은 표시가 '기본'으로만 나온다. `vehicle_powertrains`에 구동이 있어서 채울 수 있다 [추정 — 대응 규칙은 아직 안 만듦].
- 옛 배기량 칸 `displacement`는 463개가 비어 있다 [확인함]. 새 칸 `engine_cc`가 대신하므로 사이트에서 쓰는 곳이 있는지만 확인하면 된다 [추정].
- **트림 이름에 인승이 들어 있는 트림은 65개다**(`seats_src='name'`, 예: 팰리세이드 '7인승 익스클루시브') [확인함]. 화면은 이름에서 인승을 빼서 한 트림으로 묶으므로 이름 표기가 어긋나면 묶이지 않는다.
- **옵션·패키지 이름에 "(N인승)"이 붙은 줄은 78개다**(팰리세이드 옵션·패키지·외장 색상, 스타리아 계열, 카니발 하이브리드, 렉스턴, G90 인승 축) [확인함]. 색상만 트림 인승에 맞춰 고르게 고쳤다. 옵션·패키지는 9인승 트림에서도 "(7인승)" 이름 그대로 보일 수 있다 [추정 — 화면 확인 필요].
- **차량가가 차즘과 1% 넘게 다른 연결은 19개다** [확인함]. 확신 '높음'은 액티언 S8·액티언 하이브리드 S8·그랑 콜레오스 하이브리드 아이코닉·테크노 등이고, 나머지는 옛 연식 연결(확신 보통·낮음, 참고용)이다. 공식 가격표가 우선이므로 렌테일러 값이 최신 가격표와 같은지만 확인한다.
- **빠진 트림 후보 42개**(gap: in_pdf·no_pdf)는 2단계에서 하나씩 확인한 결과 '추가할 것 0개'로 결론 났다(차즘 옛 연식·옛 표시·패키지명) [확인함 — 결정표 '2단계 결과'].
- 연식: 판매 중 106차종을 차즘 최신 연식에 맞췄다 [확인함]. G90(렌테일러 2026 > 차즘 2025)·Polestar 4(2027 > 2026)는 차즘이 낮은 경우라 그대로 두었다.
- 세부 목록은 미리보기 `_data/rentailor/work/trim_structure/preview_trims_20261124_1808.csv`·`preview_combos_20261124_1808.csv`·`gap_20261124.csv`에 있다.

## 5. 판단이 바뀐 부분 (왜)
- 처음에는 '세부 트림 표를 새로 만들기'였는데, **공식 가격표 구조 유지 + 칸 추가**로 바꿨다(Q22). 고객은 제조사 가격표처럼 고르고, 조합은 차즘 연결에만 쓴다.
- 인승은 '0원 5인승 항목을 만들기'에서 **트림마다 기본 인승 칸**으로 바꿨다(결정 15). 유료 6·7인승 50줄은 추가금 옵션 그대로 둔다.
- '렌테일러에 없는 트림 35개'는 차즘 옛 줄로 밝혀져 추가 0개로 끝났다(2단계).
- Supabase 사본 반영은 동결 표라서 하지 않기로 했다(4단계). 되돌리기가 필요해지면 그때 로컬 → Supabase를 한 번 재동기화한다(승인 필요).

## 6. 우선순위·범위
- **우선**: ① 기본 인승 빈칸 17개(화물 제외) ② 구동 빈칸 178개 ③ 차량가 1% 차이 중 확신 '높음' ④ 옵션·패키지 이름 "(N인승)" 화면 확인.
- **선택**(사장님께 물어볼 것): 전기·수소 136개 엔진 구분(배터리·모터), 옛 `displacement` 칸 정리.
- **범위 밖**:
  - 화물차 봉고·포터(결정 14 보류), 수입차(임포리스 담당 — 렌테일러는 국산 + 테슬라·BYD·폴스타).
  - 렌트료 파일 코드 `chazm_terms_table.py`·AI 리포트 화면은 AI 리포트 세션 담당이다. 단, `modelYear` 칸은 이 개편에서 넣은 것이라 지우면 안 된다.
  - 운영 Supabase 쓰기.

## 7. 새 세션 첫 지시 (제약 포함)
1. 결정표를 읽고 위 4번 숫자를 로컬 DB에서 다시 확인한다(읽기만). `[추정]`으로 표시된 줄부터 확인한다.
2. 구동 빈칸 178개를 `vehicle_powertrains`에서 채우는 규칙을 만들어 **미리보기 CSV만** 만든다(DB 쓰기 금지). 차종별 표본을 사장님께 보여 드린다.
3. 기본 인승 빈칸 17개(스타리아 계열·렉스턴·레이 EV)를 공식 가격표 PDF(`_data/rentailor/collected/price_crawler/pdf_cache/`)로 확인해 채울 값 표를 만든다. 좌석 구성이 여러 개인 트림은 어느 값을 '기본'으로 할지 사장님께 묻는다.
4. 차량가 1% 차이 중 확신 '높음' 줄을 최신 가격표와 대조해 보고한다(고치지 않음).
5. 옵션·패키지 "(N인승)" 78줄이 [내 차 만들기]에서 인승이 다른 트림에 잘못 보이는지 로컬 화면으로 확인한다.

**제약**
- DB 쓰기는 미리보기 → 백업 → **사장님 승인** 뒤 로컬 DB에만 한다. 손으로 고친 값은 `engine_src`·`seats_src='manual'`로 적어서 매달 자동 채우기가 덮어쓰지 않게 한다.
- `price_crawler.py replace_trims`는 가격표가 바뀐 차의 트림을 지웠다 다시 넣는다(새 id). 그래서 칸 값은 트림 id가 아니라 '차종 + 트림 이름' 기준으로 다시 채워지는지 확인한다. 'manual'로 적은 값이 다시 넣을 때 살아남는지도 꼭 확인한다 [추정 — fill은 이름 기준이지만 manual 값은 같은 행에 있어 replace 때 사라질 수 있음].
- 사이트 반영은 `car_publish.py run --dry-run`으로 바뀔 내용을 확인한 뒤 진행한다. 이것은 cadam-web main push, 곧 배포이므로 승인을 받는다.
- 고친 뒤에는 `trim_structure_monthly.py check --dry-run`으로 새 불일치가 없는지 보고, 필요하면 `check --seed`로 기준선을 갱신한다.
